## 1. Краткое резюме проекта
CeilingsApp — это высокотехнологичный маркетплейс для рынка натяжных потолков. Проект демонстрирует глубокое понимание мобильной архитектуры (NCC, Request Router, Geo-Clustering) и модульного бэкенда на NestJS.

**Текущее состояние:** Архитектурно проект находится на уровне "Senior", однако реализация критических узлов безопасности (Auth) и интерфейса (Chat) не завершена. Приложение является "Hardened MVP", которое требует финального рывка перед выходом на 10,000+ пользователей.

## 3. Что сделано хорошо
1.  **EntityStore V11 (Frontend):** Использование нормализованного кэша (NCC) предотвращает классическую проблему React Native — рассинхронизацию данных между экранами.
2.  **Smart NLP Parser (Backend):** В `OrdersService.parseOrderText` реализована логика, которая экономит пользователю 2-3 минуты на заполнении формы заказа. Это киллер-фича для вовлечения мастеров.
3.  **Request Router:** Дедупликация запросов и кэширование на уровне сервиса — решение, достойное уровня Senior-разработки.
4.  **Spatial Indices:** Правильное использование индексов в Prisma гарантирует быструю работу карты даже при 50,000+ заказов.

---

## 4. Главные проблемы

1.  **Auth Bypass:** Любой пользователь может зайти в чужой аккаунт, зная номер телефона. Отсутствует OTP-код.
2.  **WebSocket Broadcast:** В `AppGateway` используется глобальный `emit`. Это приведет к лагам на клиентах при росте активности.
3.  **Frontend Chat Mocks:** Чаты на бэкенде готовы, но на фронтенде они статичны. Мастера и заказчики не могут договориться.
4.  **Missing Error Boundaries:** На фронтенде мало обработки 500-х ошибок, что может приводить к "белым экранам".

## 5. Критические исправления (Specific Instructions)

### [Backend] SMS Verification Logic
- **Файл:** `backend/src/modules/auth/auth.service.ts`
- **Проблема:** Метод `login` сразу возвращает токен без проверки владения номером.
- **Риск:** Кража аккаунтов, финансовые риски.
- **Решение:** Внедрить двухэтапную авторизацию: `requestOtp` -> `verifyOtp`.
- **Пример:**
```typescript
// В AuthService
async requestOtp(phone: string) {
  const code = Math.floor(1000 + Math.random() * 9000).toString();
  await this.cache.set(`otp:${phone}`, code, 300); // 5 min TTL
  return { status: 'sent' }; // В DEV возвращать code
}
```

### [Backend] WebSocket Optimization (Geo-Rooms)
- **Файл:** `backend/src/modules/gateway/app.gateway.ts`
- **Проблема:** `broadcast` шлет данные всем.
- **Решение:** При коннекте мастер подписывается на комнату своего региона (сетка 0.1°).
```typescript
// В AppGateway
@SubscribeMessage('geo.join')
handleGeoJoin(@MessageBody() data: { lat: number, lng: number }, @ConnectedSocket() client: Socket) {
  const room = `geo:${Math.floor(data.lat * 10)}:${Math.floor(data.lng * 10)}`;
  client.join(room);
}
```

### [Frontend] Chat Integration
- **Файл:** `src/screens/ChatListScreen.tsx`
- **Проблема:** Хардкодные данные в `useState`.
- **Решение:** Подключить `apiService.getMyChats()` и `EntityStore`.

## 6. Рекомендации по улучшению

### 🔥 Критично:
- **Rate Limiting:** Установить `@nestjs/throttler` (макс 100 запросов в минуту с одного IP).
- **CORS Config:** В `main.ts` ограничить доступ только списком разрешенных доменов/IP.

### ⚠️ В ближайшее время:
- **Cursor Pagination:** Добавить `take` и `cursor` в `findAll` заказов.
- **Push Notifications:** Реализовать `NotificationService` через Expo SDK.
