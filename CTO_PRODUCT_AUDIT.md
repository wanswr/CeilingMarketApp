# CTO Product & Structure Audit (clean-project)

Этот технический отчёт подготовлен в качестве аудита текущего состояния репозитория, структуры проекта и верификации требований по файлу **PRODUCT BIBLE**.

---

## 1. Выбранная версия Product Bible
Для дальнейшей разработки в качестве единственного и приоритетного источника требований выбран файл:
* **PRODUCT_BIBLE.md** (переименован из исходного `PRODUCT BIBLE v11`).

### Причины выбора:
1. **Версия документации:** Внутри файла `PRODUCT BIBLE v11` явно указана **версия v2.0** («Строительная платформа — продуктовая документация v2.0»). В то время как удалённый файл `PRODUCT BIBLE v1.0` содержал более ранние и менее подробные требования.
2. **Детализация:** Файл `PRODUCT BIBLE v11` (v2.0) содержит 28 полноценных детализированных разделов (включая разделы об удалении аккаунта, работе при плохом интернете, аналитике, матрице прав доступа и т.д.), тогда как версия v1.0 заканчивалась на 10-м разделе (Создание заказа) и была крайне поверхностной.
3. **Согласованность:** Версия v2.0 полностью покрывает весь жизненный цикл заказа, финансовую логику, логику дашбордов и роли, что критически важно для сверки реализации.

## 2. Что было удалено / исключено из ветки `clean-project`
В рамках очистки репозитория от временных файлов, логов расследований и старых архивов, следующие файлы были полностью удалены через `git rm`:

* `PRODUCT BIBLE v1.0` — устаревшая версия продуктовой документации.
* `backend_files_find.txt` — временный файл с результатами поиска файлов бэкенда.
* `orders_service_apply_context.txt` — временный контекстный файл для анализа OrdersService.
* `orders_service_imports.txt` — временный файл со списком импортов.
* `prisma_file_find.txt` — временный файл с путями до схем Prisma.
* `project_fixes.tar.gz` — неиспользуемый архив с резервными копиями исправлений.
* `search_urgency.txt` — временный файл исследования логики срочности поиска.
* `users_service_set_role_context.txt` — временный файл исследования логики смены ролей в UsersService.

## 3. Что оставлено в проекте
В новой чистой ветке оставлена только актуальная кодовая база и ключевые конфигурации:
1. **Frontend (`src/`):** Полный исходный код мобильного приложения React Native (Expo).
2. **Backend (`backend/`):** Полный исходный код NestJS API.
3. **Prisma & Миграции (`backend/prisma/`):** Схема базы данных, сиды и история миграций.
4. **Конфигурации:** Скрипты сборки, настройки линтеров, Expo, TypeScript, Jest и Detox.
5. **Assets:** Ресурсы и иконки приложения.
6. **Документация:** Файл `README.md` в корне, `backend/README.md` и переименованный файл `PRODUCT_BIBLE.md`.

## 4. Зависимости (Runtime / Build / Test Dependencies)
Следующие файлы были идентифицированы как критически важные зависимости и **не подвергались изменениям или удалению**:

* `App.tsx`, `index.ts` — точки входа React Native.
* `package.json`, `package-lock.json` — описание внешних пакетов и блокировок версий фронтенда.
* `backend/package.json` — зависимости и скрипты запуска NestJS.
* `tsconfig.json` — конфигурация компилятора TypeScript.
* `metro.config.js`, `babel.config.js`, `app.json` — конфигурация бандлера Metro и Expo.
* `detox.config.js` — конфигурация сквозного E2E-тестирования.
* `jest.config.ts` — настройки модульного тестирования.

## 5. Документация против временных файлов (Мусора)
* **Документация (Сохранено):** `PRODUCT_BIBLE.md`, `README.md`.
* **Временные файлы (Удалено):** Все файлы с расширением `.txt` в корне, содержащие технические дампы и выгрузки контекстов функций. Они захламляли дерево репозитория и создавали лишний шум при поиске по тексту.

---

## 6. Спорные файлы (НЕ удалённые и причины сохранения)
* `.circleci/` и `.github/` — сохранены в полном объёме, так как содержат конфигурационные файлы CI/CD-процессов (автоматической интеграции и тестирования). Удаление могло нарушить автоматическую сборку на удалённых серверах.
* `App.test.tsx` — сохранён, так как является частью тестового покрытия Expo-приложения, несмотря на то что представляет собой базовую проверку рендеринга.
* `e2e/` — сохранён, поскольку содержит реальные сквозные тесты Detox для тестирования мобильного приложения.

## 7. Результаты выполненных проверок
В процессе аудита структуры в ветке `clean-project` были запущены автоматические тесты и проверки:

1. **Валидация схемы Prisma (`npx prisma validate`):**
   * **Результат:** ✅ SUCCESS (Схема полностью валидна, конфликтов нет).
2. **Тесты мобильного фронтенда (`npx jest` с корректным `NODE_PATH`):**
   * **Результат:** ✅ 100% PASS (Все 3 тест-сюита и 9 тестов пройдены успешно).
   * Проверенные модули: `MapEngine.test.ts`, `MutationQueueService.test.ts`.
3. **Тесты бэкенда NestJS (`npm run test`):**
   * **Результат:** ⚠️ PARTIAL SUCCESS (10 из 11 тест-сюитов прошли успешно, 83 теста пройдены).
   * **Выявленная проблема (pre-existing):** Тест-кейс `orders-categories.spec.ts` упал с ошибкой `TypeError: Cannot read properties of undefined (reading 'findUnique')` на строке 364 в `orders.service.ts` из-за некорректного mock-окружения для модели `subscription` в тестах. Данная проблема существовала до начала очистки проекта и не связана с удалением файлов.
